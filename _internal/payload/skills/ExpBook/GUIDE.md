# 《ExpBook 冒險者手冊》

> 給「想開始用、或想推薦給別人用」的你。
> 這是一份**人讀的完整指南**——把 ExpBook 是什麼、為什麼這樣設計、怎麼開始用，一次講清楚。
> 機器讀的權威規格在 `doc/SPEC.md`，AI 每輪載入的精簡操作指引在 `SKILL.md`，實作在 `scripts/exp.cjs`。
>
> 命名規則：**ExpBook = 系統名**；**EXP = 經驗值單位**。

## 序章 — 你不是在用工具，你在養一本冒險者之書

你跟 AI 協作了幾百個小時。修過難纏的 bug、重構過爛攤子、半夜還在跟一個邏輯死磕、學到一個再也不會犯的教訓——然後呢？

那些走過的路，散在幾百個對話視窗裡，關掉就沒了。

**ExpBook 把它沉澱下來。** 每一輪工作都會被記成一筆「經歷」，累積成一條看得見的成長曲線：你打過多少場硬仗、在哪個專案磨得最深、哪項能力練得最熟、燒了多少魔力（token）跑了多遠。它不是考勤表，不是 KPI 儀表板——它是**一本會隨你冒險而變厚的冒險者之書**。

打開面板，你看到的不是「這個月績效幾分」，而是：

```
[等級] 冒險者18 精英0 指揮22 殺敵51   [消耗] 魔力50.1億(有效2.04億) 金幣$3,990
🔥 連戰 7 日 ｜ 稱號〈一字千軍〉 ｜ 徽章 8/25
```

> 上面這串是**真實數據**——某位冒險者 34 天（238 個 session、26,507 則訊息、2,129 次真實發話）跑出來的面板。下文所有範例都用這份真實基準，不是虛構數字。

零依賴、純 Node 一支腳本就跑。記錄全自動（AI 每輪結束自己沖帳），你只要偶爾喊一聲「看面板」。

## 第一章 — 公會的四條鐵律（為什麼這樣設計）

ExpBook 的每一條規則，都從這四條哲學長出來。理解它們，你就懂了這套系統「不做什麼」——而那往往比「做什麼」更重要。

### 鐵律一：看見成長歷程，不打考績

目的是**回看走過的路**，不是評分裁決你或 AI。沒有排行榜要贏、沒有分數要保。等級只是「你一路走來的累積證明」，不拿來跟誰比。

### 鐵律二：正分階梯、只進不退

**所有事件 EXP ≥ 0，永遠沒有扣分。** 連挫折、連重犯的錯，都誠實記下、給最小的正分——因為它們也是歷程的一部分。冒險路上摔過的跤，不該從你的故事裡被擦掉，但也不該讓你的等級倒退。階梯只往上，你永遠在前進。

### 鐵律三：厚程式、薄 AI

所有計算與渲染由腳本 `exp.cjs` 完成；AI 每一輪只做三件小事：**辨識你的意圖 → 發一條短指令 → 轉述一行指標**。AI 不會把整份報告念進對話佔你版面、燒你 token。要看細節，你自己開檔——乾淨俐落。

### 鐵律四：獎勵成果與學習，不獎勵掙扎

**交付**（完成一個版本）和**心得**（學到可複用的教訓）給高分；苦工、失敗、重犯只給 +1。而且**不按 token 數或對話輪數計分**——因為那會誘導「為刷分而灌水」。燒得多不等於做得好。這條鐵律後面還會再出現一次（消耗儀表板刻意用「代價」框架），它是整套系統的良心。

## 第二章 — 你的成長三條線（基底模型）

每一筆「經歷」會同時餵養**三條成長線**。記一筆工作，這三條線一起長 EXP：

| 線 | 名稱 | 它代表 |
|----|------|--------|
| All | **冒險者等級** | 所有經歷累積 ＝ 你的總成長 |
| tag① | **地城（專案）** | 每筆**必帶**；跨專案累積熟練度。一資料夾 ＝ 一地城 |
| tag② | **技能（能力）** | 每筆**選填、可多項**；你在這輪練到了哪些本事 |

- **升級門檻**：每 **1000 EXP** 升一級（`等級 = ⌊總EXP / 1000⌋ + 1`）。
- **地城**：沒指明專案時，自動歸到預設地城「**日常訓練(雜項)**」。同一個資料夾的工作會累積成那座地城的熟練度。
- **技能**：預設 7 項恆顯示——**除錯 / 架構 / 實作 / 重構 / 研究 / 工具 / 知識**——但你可以自由新增任何技能 tag。技能多了會列成扁平長串，所以面板用「分類小計」呈現（核心 6 類 + 工具鏈 5 類），純渲染、不動原始資料。

### 五種經歷（kind）——正分階梯怎麼記

每筆經歷帶 1 個 kind。這是整套計分的核心：

| kind | 名 | EXP | 什麼時候記 |
|------|----|-----|-----------|
| `task` | **任務** | **+200** | 明確交付、做完並驗證的一個版本 |
| `lesson` | **心法** | **+20** | 犯錯修正後學到的**可複用新**心得（禁灌水、禁複述舊的） |
| `chore` | **練功** | **+1** | 有做事但不構成交付：調查、跑指令、搬檔、部分進度（日常心跳） |
| `fail` | **敗戰** | **+1** | 試了沒成、死路、沒得到心得（新傷） |
| `regress` | **常錯** | **+1** | 重犯**已知**的錯（舊傷復發） |

**怎麼分？** 一句口訣：

> 有可用產出 → **練功**；死路沒產出 → **敗戰**；死路且重犯已知錯 → **常錯**。
> 而「**敗戰 vs 常錯**」只問一句：**這個錯以前犯過嗎？** 沒有 → 敗戰；有 → 常錯。

注意 task 給 +200、其餘最高才 +20，最低 +1——這就是鐵律四的數字化身：**成果與學習值錢，掙扎只給心跳分**。

## 第三章 — 四種等級軸 ＋ 兩道消耗儀表

基底（第二章）之上，ExpBook v2.5 疊了一層更立體的敘事。面板用「‖」把世界切成兩半：**左邊是會升級的榮譽，右邊是只增不減的代價**。

> **重要前提**：這一層**全部純衍生、零 EXP 入口**。它只是換個角度回看你已經產生的資料（對話記錄裡的 token 用量），**完全不影響第二章的 EXP 經濟**，也絕不誘導你去刷。

### 榮譽組：四種等級軸（皆只進不退）

| # | 名稱 | 錨定什麼 | 曲線 |
|---|------|---------|------|
| ① | **冒險者等級** | 成果量（task +200 等現有 EXP） | 線性，現狀不動 |
| ② | **精英冒險者** | 高價值成果（只吃 task，依委託規模加權 D1/C2/B3/A5/S8） | 指數累進，**冒險者 LV50 才解鎖** |
| ③ | **指揮等級** | 你真打字的對話次數（排除權限 Enter／系統注入） | 平方根 |
| ④ | **殺敵等級** | 你的輸入文字量（扣掉可偵測的 code，標 code%） | 平方根 |

- **成果組（①②）**＝你產出了什麼。① 驗收制無灌水；② 後期門檻指數爬升，逼你去拼真正的精英任務（原本設計成 ×1.5 太陡，跑到精英 Lv10 要 15 年，已改 ×1.2：前期溫和、中後期穩爬）。
- **投入組（③④）**＝你付出了多少，且抗灌水。③ 幾乎刷不動（系統注入的訊息被濾掉）；④ 含貼上的非 code 文字（量測不出手打 vs 複製，所以誠實標成「輸入文字量」而非「純手打」）。
- 為什麼不直接用 `input_tokens` 當投入錨？因為它混了系統與工具的 token、又被長對話自動灌水，失真。

**精英曲線長相**（`cost(n) = round(500 × 1.2^(n-1))`，累計門檻）：

```
 Lv1   500     (累 500)
 Lv5   1,037   (累 4,318)
 Lv10  2,580   (累 16,000)
 Lv20  16,000  (累 ~100,000)
```

### 代價組：兩道消耗儀表（只增不升級）

| # | 名稱 | 錨定 | 範例（真實 34 天） |
|---|------|------|-------------------|
| ⑤ | **魔力消耗** | 總 token 處理量 | 50.1 億（其中有效 2.04 億；其餘 ~96% 是 cache_read「重複翻舊帳」） |
| ⑥ | **金幣消耗** | token → $（依現行定價估算） | $3,990 USD |

為什麼把消耗做成「代價」而不是「戰功」？**這是鐵律四的再次現身。** 用「魔力被燒掉、金幣被花掉」的負面框架，刻意弱化炫耀感——避免有人為了「魔力數字好看」去灌 token。資料完整保留給你回看，但絕不誘你刷。金幣也不拿來當等級（定價會變，變了只重算展示，不動任何等級）。

### 一行式面板長相

數字用**中文數量級**（億／萬字），不用 B/M：

```
[等級] 冒險者18 精英0 指揮22 殺敵51   [消耗] 魔力50.1億(有效2.04億) 金幣$3,990
```

左半「[等級]」＝會升級的榮譽（成果＋投入），右半「[消耗]」＝只增的代價。一眼看完你這趟冒險的全貌。

> 校準參考（同一份真實數據）：對話 2,129 次 → 指揮約 Lv23；打字純文字 150.2 萬字 → 殺敵約 Lv50。

## 第四章 — 榮譽收藏：四元素

等級是連續的曲線，**四元素**則是離散的、會「叮」一聲解鎖的收藏品。它們全部**純衍生、零 EXP、再怎麼觸發都不誘刷**——只是把你早已做過的事，換成值得收藏的形式呈現。

### 元素一：徽章（25 枚・六類・五階稀有度）

稀有度由低到高：**N → R → SR → UR → LR**。初版 25 枚分六類：

| 類別 | 徽章（稀有度・條件） |
|------|---------------------|
| **A 戰績** | 初試啼聲(N，首個 task)／百戰之身(R，100)／千錘百鍊(SR，1000)／萬卷功成(LR，10000) |
| **B 投入** | 見習指揮官(N，指揮 Lv10)／沙場宿將(SR，指揮 Lv50)／筆鋒如刃(R，殺敵 Lv25)／一字千軍(SR，殺敵 Lv50) |
| **C 委託** | 首級(N，首個 S 級)／全階通吃(R，D~S 各 ≥1)／S 級獵人(SR，累積 10 個 S)／巨龍討伐者(UR，單委託 > 1000 萬 token) |
| **D 代價**（負面自嘲） | 億級法師(R，有效 1 億 token)／燒錢如焚(SR，$1000)／揮金如土(UR，$5000)／〈你知道燒了多少嗎〉(SR 隱藏，$3000 吐槽) |
| **E 習慣** | 夜術士(R，0–5 點完成 task)／晨型冒險者(R，5–8 點)／假日狂戰士(R，週末)／不眠騎士(SR，單日用 >12hr)／馬拉松(SR，單 session >6hr) |
| **F 隱藏/幽默** | 浴火重生(R，連 3 敗後達成)／惜字如金(N，<10 字完成 task)／話癆(N，單日 >50 對話)／手滑藝術家(N，常錯累積 3 次) |

連「燒錢」「重犯」都做成徽章——這套系統的態度是：**你的故事連同糗事一起收藏，但永遠用善意的方式。**

### 元素二：稱號

從你已解鎖的徽章自動衍生一個頭銜，掛在面板名字旁。規則：**最高稀有度 × 最新解鎖**（隱藏徽章不列入稱號候選）。也可以在 `STATUS.md` 手動釘選你喜歡的稱號覆寫。範例那位冒險者的稱號是〈一字千軍〉（殺敵 Lv50 的 SR 徽章）。

### 元素三：streak 連戰（反焦慮版）

連續活躍日 ＝ 當日至少完成 1 個 task。面板顯示 `🔥N`。但 ExpBook 的 streak **刻意設計成不讓你焦慮**：

- **護符機制**：每週自動發 1 枚連戰護符，斷 1 天會自動消耗護符、不算斷。
- **不歸零羞辱**：真的斷了，當前連戰歸 0，但**最長連戰（PR）永久保留**——你的最佳紀錄不會被抹掉。
- 只看出勤、不看量。今天哪怕只交付一件小事，連戰就續上了。
- 里程碑：7 / 30 / 100 / 365 日。

### 元素四：隨機彩蛋（flush 時一行・純 flavor・全無獎勵）

每輪沖帳時，**可能**冒出一行小驚喜（薄 AI、零收益，只是讓回看多點溫度）：

| 類型 | 觸發 |
|------|------|
| 每日寶箱 | 當日首次沖帳 |
| 暴擊 | 刷新個人紀錄（PR） |
| 連擊慶祝 | streak 達 7 / 30 整 |
| 里程碑炸裂 | 跨億 token／整百 task／破 $ 關 |
| 稀有遭遇 | ~3% 機率的隨機台詞（唯一的隨機項，純 flavor） |

絕大多數彩蛋是**條件觸發**（你真的達成了什麼），隨機只佔「稀有遭遇」且毫無收益——連彩蛋都守住「不誘刷」的底線。

### 元素五：個人 PR 里程碑

四項個人紀錄即時播報並寫進面板：**單日最高 token／單日最多字／單委託最大／最長連戰**。刷新的那一刻會「暴擊！」一下——這是你跟自己的競賽，永遠只跟昨天的自己比。

## 第五章 — 生涯燃料儀表板（你的全帳本）

等級與徽章講「你成長到哪」，燃料儀表板講「你燒了多少燃料跑到這」。**不升級、不評分，純粹是人話化的生涯統計。**

### 委託討伐記錄 D/C/B/A/S

把你的 task 依「規模」分五級。規模 ＝ 該 task 與前一筆 task 之間，所有對話消耗的計費等效 token（時間區間歸屬）。**跨多個 session 的大項目會自動合併成 1 件委託**——解決「大專案被切成好幾段、看起來像好幾件小事」的死穴。

| 級 | 計費等效 token | 真實 34 天件數 |
|----|----------------|---------------|
| D | < 17 萬 | 54 |
| C | 17–33 萬 | 60 |
| B | 33–76 萬 | 58 |
| A | 76–180 萬 | 35 |
| S | > 180 萬 | 24 |

中間沒有 task 的純探索 token 不形成委託，只進總統計——不會憑空灌出戰功。

### token 流量四分項（人話化）

| 分項 | 人話 | 真實 34 天 |
|------|------|-----------|
| input | 輸入 | 7.2M |
| output | AI 寫出 | 28.2M |
| cache_write | 首次建快取 | 168.5M |
| cache_read | 重複讀歷史 | 4,806M（~96%，所以「有效」只算前三項） |

### 其餘生涯統計（真實 34 天）

- **對話次數**：2,129 次（你主動打字發話；權限 Enter 與系統注入不算，是近似值不當精確）。
- **打字量**：208.2 萬字（其中 code 28%，純文字 150.2 萬字）。jsonl 不記輸入來源，手打 vs 複製貼上量測不出，所以標「輸入文字量」而非「純手打」——誠實不假精確。
- **使用時間**：116.6 小時（相鄰訊息間隔 <15 分才累加，避免把「掛著沒動」算進去）。
- **書本換算**：計費等效 × 0.7 字/token，每 10 萬字 ＝ 1 本。把你的協作量換成「寫了幾本書」。
- **等效成本**：≈ $3,990 USD（Opus4.7 $1999 ＋ Opus4.8 $1760 ＋ Sonnet $160 ＋ Haiku $24）。

## 第六章 — 啟程：如何開始冒險

### 安裝與資料位置

ExpBook 是一支純 Node 腳本（`scripts/exp.cjs`），**零依賴**。資料存在「腳本所屬 CLI home」的 `expbook/` 下：

- Claude Code → `~/.claude/expbook/`
- Gemini CLI → `~/.gemini/expbook/`
- 想改位置 → 設環境變數 `EXPBOOK_HOME` 覆寫（最高優先）。

雙 CLI 各自獨立、互不干擾。資料夾結構：

| 檔案 | 角色 |
|------|------|
| `log.jsonl` | **唯一事實來源**，一行一事件，只新增不修改 |
| `state.json` | 由 log 重算的快取，可隨時 `rebuild` |
| `STATUS.md` | 玩家面板（每次 `status` 重新產生） |
| `views/*.md` | 各式檢視報告（歷程／某地城／某技能／某期間） |
| `achievements.json` | 四元素衍生快取 |
| `config.json` | 你的個人化覆寫（EXP 數值、釘選稱號…） |

### 日常使用：你只要動嘴

**記錄是全自動的。** 機制叫 A+C：AI 在回合中判斷「這值得記」就暫存（stage），**Stop hook 每輪結束自動沖帳（flush）進 log**。你不用記任何指令。

你唯一要做的，是想看的時候**喊一聲**——用大白話，AI 自動翻成指令：

| 你說（中英夾雜都認） | 背後指令 |
|---------------------|---------|
| 檢視玩家面板 / 現在幾級 / show ExpBook status | `status` |
| 看歷程 / 我最近做了什麼 | `history [篩選]` |
| 這輪加了什麼 EXP / 剛剛為什麼加分 | `lastflush` |
| 本週做了什麼 / 週報 / 這個月幹了啥 | `report --since 本週\|本月` |
| 看 X 地城 / 這專案做過什麼 | `dungeon X` |
| 看 X 技能 / 我這能力練多少 | `skill X` |
| 有哪些指令 / ExpBook help | `help` |

AI 只會轉述 stdout 那一行指標，細節報告請自己開檔看（鐵律三：薄 AI）。

### EXP 透明、可調整

- **入帳當下可見**：stage 會回顯「✎ staged 心法 (+20 EXP)」；flush 印出本輪每筆明細，並存進 `_last_flush.txt`。
- **隨時回查本輪**：喊「這輪加了什麼」→ `lastflush`。
- **改每種 kind 的 EXP 數值**：在 `expbook/config.json` 寫 `{"exp_of":{"task":150,"lesson":30}}`。**只影響之後的新事件**——歷史事件把當時 EXP 存死了，改 rate 不回溯竄改。
- **校正/回退某筆**：`remove --last｜--ts "<時間戳>"｜--match "<事由片段>"`，移除後自動重算。

### 給 AI 的一個提醒：事由要寫得對得起未來的自己

記錄品質的關鍵在「事由（reason）」。它要讓未來回看時能還原當時情境，**不可一兩句帶過**。好的事由至少涵蓋：① 具體做了什麼（逐項，不是「修了東西」）② 涉及哪些檔案／模組／函式 ③ 結果如何（成功／失敗／部署；有 commit 附 hash）④ 為何而做。

- ✅ 好例：「修好 Arena 戰鬥結算 off-by-one：結算 hp 多扣 1（`damage.lua:42` floor→round），改回後 E2E smoke 3 場通過，commit a1b2c3」
- ❌ 壞例：「修好 Arena bug」

> 安全網：Stop hook 偵測到「有新 commit 但本輪沒記」會在下一輪提醒補記。

## 附錄 B — FAQ

**Q：這會不會變成另一個逼我衝業績的 KPI？**
不會。鐵律一就釘死了：看歷程不打考績。沒有排行榜、沒有扣分、沒有人拿這個評你。它是給你自己回看的書，不是給別人打分的表。

**Q：我擔心 streak 斷掉的壓力。**
ExpBook 的 streak 是反焦慮設計：每週自動發護符（斷 1 天不算斷），就算真斷了也只是當前連戰歸 0，你的最長紀錄永久保留。它鼓勵出勤，但不羞辱缺勤。

**Q：消耗那些數字（token、金幣）會不會誘我去灌水？**
刻意不會。消耗用「代價」框架（魔力燒掉、金幣花掉）弱化炫耀，而且 token／對話數**完全不轉成 EXP**。等級只認成果與學習。燒得多 ≠ 等級高。

**Q：AI 會不會把一堆報告念進對話、佔我版面？**
不會。鐵律三「薄 AI」：AI 每輪只發一條短指令、轉述一行指標，報告細節你自己開檔看。

**Q：我可以自訂嗎？**
可以。EXP 數值（`config.json`）、技能 tag（自由新增）、技能分類（改 `SKILL_GROUPS` 表）、釘選稱號、資料位置（`EXPBOOK_HOME`）都可調。

**Q：資料安全嗎？會不會被改壞？**
`log.jsonl` 是 append-only 的唯一事實來源，其餘都是可重算的衍生快取（`rebuild` 一鍵重建）。每次遷移都留 `.bak` 備份。
